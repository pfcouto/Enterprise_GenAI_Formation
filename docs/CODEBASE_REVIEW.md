# Codebase review: what was wrong, what was fixed, what is left

Review of the whole formation workspace (code, Docker stack, notebooks, speaker and participant guides) done before the dataset rebuild. Every item was checked by reading the code and, where possible, by running it. Items marked **fixed** were fixed in the same pass and verified by running the stack end to end; **open** items are deliberately left or need a decision from you.

## A. Findings that made the demo misleading (all fixed)

| # | Finding | Why it mattered | Status |
|---|---|---|---|

The text invented facts (ezSearch "Active Green / Standby Red" clusters, 99.99 % SLA, `ERR_EZSEARCH_FAILOVER_9901`, `proxy-green.syone.internal`) that syone.com does not publish. | Participants would learn that a RAG system "knows" things about Syone that are false. | 2 | The "images" of the Syone corpus were diagrams drawn with Pillow, not from the website. The real site has almost no informative images (215 found: stock photos and banners). | Fake visual grounding. | **fixed**: 4 hand-reviewed, genuinely informative images with written descriptions |
| 3 | Hardware corpus: one PDF, five fault codes, claimed to be "Open Compute Project" data and named a real Broadcom ASIC. | Too thin to show retrieval differences; a false provenance claim. | **fixed**: 8 manuals, 30 codes, 9 figures, clearly labelled fictional |

## B. Findings that would have broken a live session (all fixed)

| # | Finding | Status |
|---|---|---|
| 11 | `langfuse/langfuse:3` was started with only Postgres. Langfuse v3 also needs ClickHouse, Redis and S3-compatible storage; the container would not become healthy. No project or API keys were provisioned, so the keys in `.env` did not exist. | **fixed**: full v3 stack, **headless init** so the keys in `.env` work immediately (login `syone@syone.com` / `syone2026`) |
| 12 | All five free models in `litellm_config.yaml` have been retired from OpenRouter; the fallback list referenced names that are not model aliases; the UI offered any OpenRouter id but the gateway could only route the aliases. | **fixed**: current free models, valid fallbacks, wildcard route, `formation-local` alias for LM Studio/Ollama; the config explains how to refresh the list |
| 13 | `frontend/Dockerfile` copies `./public`, which does not exist, so the image build fails. An unused dependency (`@astryxdesign/*`) was advertised as the UI library. | **fixed** (`public/` added, dependency removed, claim removed) |
| 14 | Prometheus got `401` from the gateway's `/metrics`; a Grafana panel queried a metric nobody exports (`http_requests_total`). | **fixed** (auth header; panel now uses `syone_requests_total`) |
| 15 | The API image installed Docling and torch (several GB) although the API does not use them. | **fixed**: slim runtime requirements; heavy tools run on the host (root `requirements.txt`) |
| 16 | `download_models.py` instantiated `DocumentConverter()`, which downloads nothing. Attendees would still wait for downloads mid-session. | **fixed** (`download_models.py --download` really downloads; `--check` verifies) |
| 17 | Qdrant point ids came from Python's randomized `hash()`; `client.search` is deprecated; paragraph chunking destroyed tables; every image of a corpus was attached to every document. | **fixed**: UUIDv5 ids (idempotent re-index), `query_points`, table-row chunks, figures bound by caption |
| 18 | Docling escapes underscores in Markdown, which silently breaks exact search for codes like `0x4A7B_VRM_OVERVOLT`. A PDF table column also split a code across two lines. | **fixed** (unescape in the parser; narrow-column guard in the PDF builder; `validate_dataset.py` checks all 30 codes) |
| 19 | The text-only LLM never sees images: "visual grounding" only meant that a filename appeared in the answer. | **improved**: every figure carries a text description, so text inside images is retrievable; the model is given the descriptions and told which paths it may cite. | 20 | The golden set had 5 questions and no check that they were answerable. | **fixed**: 34 questions, retrieval metrics separate from answer metrics, `validate_dataset.py` proves answerability |

## C. Open items and caveats

1. **Training agenda document.** *Resolved 2026-10-25:* the agenda and goals documents now follow the three 55-minute sessions; "active vs standby architecture diagrams" and "Opik GEPA" are gone (the demo was based on invented facts; Opik is deferred). The deck `Documents/Enterprise AI Engineering - UP Skill 2026.pptx` was built from the UP Skill template.
1a. **Prometheus could not scrape the gateway** when `LITELLM_MASTER_KEY` in `.env` differed from the demo key hard-coded in `config/prometheus.yml` (target DOWN, 401; the Grafana gateway panels stayed empty). *Fixed 2026-10-25:* Prometheus now reads the key from `.env` through a credentials file written at start-up.
1b. **The keyword scorer missed correct refusals** worded as "I don't have that information... contains no...". Found by the LLM judge panel; *fixed 2026-10-25* (`REFUSAL_RE`).
2. **GLM-OCR: CPU inside Docling, GPU through LM Studio.** *Update 2026-11-16: GLM-OCR was removed from the code after this measurement (18 times slower than the standard pipeline even on the GPU, and it lost a table); notebook 01 section 3 keeps the comparison.* Verified from Docling's own log (`Removing MPS from available devices ... Using device: cpu`): its Transformers VLM engine does not support Apple's GPU, so the default backend takes about 6 minutes per page. The new `--glm-backend lmstudio|ollama` sends pages to a local GGUF build served on the GPU: about 7 s per page, the full 62-page hardware corpus in 9.5 minutes, all 30 fault codes intact. It needs LM Studio (or Ollama) running with the `glm-ocr` model loaded; `mlx-vlm` stays uninstalled (it conflicts with Docling's `transformers<5.9` pin).
3. **Free models are volatile and capped.** OpenRouter limits free accounts to **20 requests/minute and 50/day** (1,000/day with $10 credit); one full evaluation consumed the day's quota and the agent track then hit `429 free-models-per-day`. The gateway client retries 429/502/503 with backoff, but a daily cap cannot be retried away. **Resolution:** provider #1 is now OpenCode Zen's **pay-as-you-go** `deepseek-v4.1-flash` (the full two-track evaluation cost about $0.28), OpenRouter free models are the fallback, and trainees use gateway **virtual keys** (one alias, budget, rate limit) instead of provider keys. See `docs/AI_GATEWAY_FAILOVER.md`.
3a. **OpenCode free models and Go cannot be used as an API backend.** Zen's free models answer `FreeTierError: OpenCode's free tier can only be used from within OpenCode` even with a valid key, and the Console states *"Free-tier chat models require OpenCode"*; Go is documented for "OpenCode and other coding agents" (it requires an `x-opencode-session` header and its own client user agent and monitors traffic). I did not work around this. The paid Zen endpoint (`https://opencode.ai/inference/openai/v1`) is documented for direct API use and works.
3b. **The prompt-optimization loop is now verified end to end** on the hosted model: naive 3/8, precise 3/8, precise + figure rules 7/8 (`docs/eval_results/prompt_optimization_formation-fast.json`).
4. **Evaluation is keyword based.** It is deterministic and cheap but cannot judge paraphrase or reasoning quality. The optional LLM judge (`judge: true`) adds a graded score; calibrate it before trusting it.
5. **The Aurora corpus is synthetic.** Questions about it test the pipeline, not domain knowledge. Some small inconsistencies written by the generating model were left in on purpose (documented in `DATA_PIPELINE_AND_SOURCES.md`).
6. **The `.venv` in this folder was created before the folder was renamed.** Its console scripts (`pip`, `jupyter`...) have absolute paths of the old location. `.venv/bin/python -m pip ...` works; or recreate it: `rm -rf .venv && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`.
7. **Security of the demo defaults.** Neo4j, Grafana, Langfuse and the gateway use well-known demo credentials and `ENCRYPTION_KEY` is all zeros. Fine on a laptop; change them before exposing any port.
8. The Syone snapshot is dated (`_manifest.json`). A page that changes upstream will differ from the golden answers: re-run `validate_dataset.py` after every re-scrape.
